CBOR Major Type Reference
Each CBOR byte: [major type: 3 bits] [additional info: 5 bits]
0 (0x00-0x1b) Unsigned integer
1 (0x20-0x3b) Negative integer
2 (0x40-0x5b) Byte string
3 (0x60-0x7b) Text string
4 (0x80-0x9b) Array
5 (0xa0-0xbb) Map
6 (0xc0-0xdb) Tag
7 (0xe0-0xfb) Simple/Float
Additional info: 0-23 = value inline, 24 = 1-byte follows, 25 = 2-byte, 26 = 4-byte, 27 = 8-byte, 31 = indefinite length
Canonical CBOR: Cardano requires canonical encoding for all hashed data. This means: smallest integer encoding, definite-length arrays/maps, sorted map keys. If your CBOR encoder produces non-canonical output, your block hashes will differ from the Haskell node's.

Transaction Body Encoding: Pre-Alonzo vs Post-Alonzo

The most breaking change in Cardano's CBOR history: Alonzo switched transaction bodies from positional arrays to labeled maps. This means the same logical transaction has completely different byte-level encoding depending on era.

Shelley/Allegra/Mary (Array)
-- tx_body as CBOR array 84 -- array(4) 82 -- inputs: array(2) 82 5820 abcd..00 00 -- [hash, index] 82 5820 ef01..00 01 81 -- outputs: array(1) 82 5820 addr.. 1a 05f5e100 1a 00030d40 -- fee: 200000 1a 02faf080 -- ttl: 50000000 -- Fields are POSITIONAL -- [0]=inputs [1]=outputs [2]=fee [3]=ttl -- Missing fields = shorter array -- Optional fields appended at end
Alonzo/Babbage/Conway (Map)
-- tx_body as CBOR map a4 -- map(4) 00 -- key 0: inputs 82 -- set of 2 82 5820 abcd..00 00 82 5820 ef01..00 01 01 -- key 1: outputs 81 82 5820 addr.. 1a 05f5e100 02 -- key 2: fee 1a 00030d40 03 -- key 3: ttl 1a 02faf080 -- Fields are KEYED -- New fields get new keys (e.g. 13=collateral) -- Keys MUST be sorted (canonical CBOR) -- Unknown keys must be preserved!
Multiplexer Frame: Encoding a ChainSync MsgRollForward
Multiplexer Frame
-- 8-byte mux header + CBOR payload 00 00 00 2a -- timestamp: 42 μs 00 02 -- protocol: 2 (ChainSync) 00 1c -- payload length: 28 bytes -- Then the CBOR message follows: 82 -- array(2): [msgId, payload] 02 -- msgId: 2 = MsgRollForward 82 -- array(2): [header, tip] ... -- era-tagged header ... -- current tip point
Era Wrapping (HFC)
-- The header inside MsgRollForward -- is wrapped by the HFC: 82 -- array(2) 06 -- era index: 6 = Babbage d8 18 -- tag(24): CBOR-in-CBOR 59 01a0 -- bstr(416): header bytes 82 ... -- actual header content -- Era indices on mainnet: -- 0=Byron 1=Shelley 2=Allegra -- 3=Mary 4=Alonzo 5=Babbage -- 6=Conway -- tag(24) means "embedded CBOR" -- The header is DOUBLE-encoded! -- You must decode the bstr, THEN -- decode the CBOR inside it.
The Canonical Encoding Trap
✓ Canonical (Correct)
-- Integer 42: 18 2a -- 1-byte uint: 42 -- Integer 0: 00 -- inline uint: 0 -- Integer 23: 17 -- inline uint: 23 -- Integer 24: 18 18 -- 1-byte uint: 24 -- Map {1: "a", 2: "b"}: a2 01 61 61 02 61 62 -- keys sorted: 1, 2
✗ Non-Canonical (WRONG)
-- Integer 42: 19 00 2a -- 2-byte uint: 42 -- WRONG: could fit in 1 byte! -- Integer 0: 18 00 -- 1-byte uint: 0 -- WRONG: 0 fits inline! -- Integer 23: 18 17 -- 1-byte uint: 23 -- WRONG: 23 fits inline! -- Integer 24: 19 00 18 -- 2-byte uint: 24 -- WRONG: fits in 1-byte! -- Map {2: "b", 1: "a"}: a2 02 61 62 01 61 61 -- WRONG: keys not sorted! If you hash non-canonical CBOR, your hash ≠ Haskell node's hash. Blocks rejected. Consensus failure.
