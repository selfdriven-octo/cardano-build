Connection Lifecycle

The complete journey from TCP socket to running mini-protocols — covering the Handshake protocol, version negotiation, network magic validation, peer classification, and connection management. This is the first thing that must work before any other protocol can start.

First Contact: When two Cardano nodes connect, the very first bytes exchanged are the Handshake protocol. The initiator proposes supported versions with parameters (including network magic). The responder picks the highest mutually supported version. If version negotiation fails — wrong network magic, no common version, parameter mismatch — the connection is immediately terminated. No ChainSync, no BlockFetch, nothing.

Network magic is the first line of defence against cross-network contamination. A mainnet node will immediately reject a connection from a preprod node because the magic values don't match. Your private testnet for the challenge will have its own magic value set in the genesis configuration.

Peer Classification (Ouroboros Peer Selection Governor)
The Haskell node classifies peers into three temperature tiers. Connections are promoted and demoted based on usefulness.
Peer Selection Governor — The Decision Engine
Cold Peers — Known but not connected ├─ Source: topology file, DNS, peer sharing, ledger peers ├─ Target count: 100-200 └─ Action: periodically promote some to Warm Warm Peers — TCP connected, handshake complete, but not active ├─ Mini-protocols established but idle ├─ Target count: 20 (configurable) ├─ Promotion: if we need more active peers → promote to Hot └─ Demotion: if too many warm peers → demote to Cold (disconnect) Hot Peers — Fully active, running all mini-protocols ├─ ChainSync, BlockFetch, TxSubmission, KeepAlive all running ├─ Target count: 20 (configurable, typically same as warm) ├─ Scoring: RTT (from KeepAlive), block fetch performance, tip freshness └─ Demotion: if performing poorly → demote to Warm or Cold Churn — Periodic rotation to discover better peers ├─ Every ~200-300 seconds: demote a random hot peer to warm ├─ Promote a warm peer to hot ├─ Connect to new cold peers └─ This prevents network ossification and helps relay diversity
